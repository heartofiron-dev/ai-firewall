# AI Firewall v1.1.0 本机 Loopback 实验结果

## 测试范围

本报告记录 `lab-simulate` 在项目所有者电脑上的一次实际运行。实验通过 TCP Socket 产生真实的本机回环连接，但不使用包级抓包、系统账户、真实凭据、漏洞利用、恶意软件或 Windows 防火墙变更。

为了避免公开本机细节，本报告不记录主机名、用户名、临时源端口、临时目标端口、进程列表或其他真实网络连接。原始 `lab-test-report.json` 由 `.gitignore` 排除，不提交仓库。

## 三模型对比流程实测

额外使用测试套件中的 60 条确定性合成记录执行一次三模型对比。三种模型共享按时间划分的 30 条训练记录、12 条阈值校准记录和 18 条独立测试记录；目标校准误报率为 `0.0`，随机种子为 `7`。

| 模型 | 版本 | Precision | Recall | FPR | TP / FP / TN / FN |
|---|---:|---:|---:|---:|---:|
| 项目内置逻辑回归 | built-in | 1.0000 | 1.0000 | 0.0000 | 9 / 0 / 9 / 0 |
| Isolation Forest | scikit-learn 1.9.0 | 0.0000 | 0.0000 | 0.0000 | 0 / 0 / 9 / 9 |
| LightGBM | 4.7.0 | 1.0000 | 1.0000 | 0.0000 | 9 / 0 / 9 / 0 |

这组数据故意让攻击与正常记录高度可分，且独立测试集只有 18 条，因此数值只证明三种适配器能在相同时间边界下完成训练和评分。它不能用于宣称 LightGBM 或内置逻辑回归在真实网络上达到 100% 准确率，也不能据此启用自动封禁。

## 本次实验发现的回归

第一次实际运行时，单独命中 `SUSPICIOUS_PORT` 的规则分数为 `0.66`。经过规则保底系数 `0.90` 后得到 `0.594`，低于默认告警阈值 `0.60`，因此规则虽然被记录，却没有形成告警。

v1.1.0 将该规则分数调整为 `0.67`，使规则保底结果为 `0.603`，并增加“单独命中可疑端口也必须越过默认阈值”的回归测试。修复后实际 loopback 场景通过。

## 复现方法

```powershell

ai-firewall lab-simulate --confirm LOCAL-LAB --output lab-report.json
```

只运行单个场景：

```powershell
ai-firewall lab-simulate --scenario port-scan --confirm LOCAL-LAB
```

## 限制

- 这是实际 loopback Socket 行为，不验证 Windows `pktmon`、物理网卡或虚拟网卡抓包链路。
- 包数量由 Socket 操作或字节数估算，不是包级采集结果。
- 虚拟认证拒绝来自程序自己的无害服务，不接触 Windows、SSH、RDP 或其他真实账户。
- 本实验适合验证功能与受控攻击形态召回，不能替代获授权、脱敏、跨日真实正常流量的误报基线。
- 通过本报告不代表项目适合自动封禁或生产部署。
